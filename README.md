# Adaptive Digital Literacy Trainer

Это веб-приложение для адаптивной практики по цифровой грамотности. Оно хранит историю ответов студента, оценивает вероятность правильного ответа на доступные задания и выбирает следующее задание с учётом текущих результатов, сложности и повторяемости.

Проект состоит из клиентской части на React и серверной части на FastAPI. Для хранения данных используется SQLite, а модели машинного обучения построены с помощью scikit-learn.

## Возможности системы

Студент может зарегистрироваться, войти в систему, выполнять задания в смешанном режиме или по выбранному навыку, проходить экзамен и смотреть свой прогресс. После ответа сохраняются правильность, время выполнения и версия модели, которая использовалась для прогноза.

Преподавателю доступны общая статистика, результаты по навыкам и студентам, банк заданий и экзамены. Администратор дополнительно может управлять пользователями и версиями ML-моделей.

В системе предусмотрены три роли: student, teacher и admin. Для авторизации применяются access- и refresh-токены JWT. Пароли сохраняются в виде PBKDF2-SHA256-хешей.

## Как работает адаптивный подбор

Для каждой пары студент — задание модель оценивает вероятность правильного ответа P(correct). В текущей версии используется 39 признаков. Они описывают общую историю студента, результаты по отдельному навыку, последние ответы, время выполнения, повторение конкретного задания и его характеристики.

Вероятность, полученная от модели, используется отдельным алгоритмом подбора. При выборе учитываются близость к целевой вероятности успеха 0,70, слабость навыка, новизна задания, неопределённость прогноза, когнитивный уровень и недавние повторы. Благодаря этому статистический прогноз отделён от правила, по которому принимается педагогическое решение.

Общий порядок работы выглядит так:

история попыток
формирование признаков до текущего ответа
проверка качества датасета

разделение train/validation по студентам
сравнение 8 конфигураций моделей
выбор и обучение итоговой модели
сохранение модели и метаданных
прогноз вероятности ответа
ранжирование заданий
сохранение прогноза и новой попытки


Сравниваются восемь конфигураций четырёх семейств: Logistic Regression, Random Forest, Extra Trees и HistGradientBoosting. Для каждого семейства используются две конфигурации. Активной выбрана модель hgb\_regularized-20260917105441-b6e211 семейства HistGradientBoosting.

## Данные

В демонстрационной базе находится синтетический набор из 14 400 попыток, 180 обучаемых, 120 заданий и 6 навыков. Он нужен для воспроизводимого запуска обучения и исследовательских сценариев.данные не являются результатом эксперимента с реальными студентами.

При проверке качества пользователи разделяются между обучающей и проверочной выборками без пересечения. Для активной модели получены следующие показатели на отложенной выборке:

|Метрика|Значение|
|-|-:|
|ROC-AUC|0,776|
|PR-AUC|0,817|
|Brier score|0,189|
|Log Loss|0,559|
|F1|0,765|
|ECE|0,022|

## Исследовательская проверка

Качество прогноза само по себе не показывает, помогает ли подбор быстрее освоить материал. Поэтому дополнительно проведена синтетическая симуляция, в которой сравниваются случайная стратегия, подбор по сложности, выбор слабого навыка и ML-адаптивная стратегия.

В основном прогоне участвовали 60 синтетических обучаемых, для каждого использовался горизонт в 90 заданий. Критерий мастерства задавался как среднее латентное мастерство не ниже 0,70 при значении каждого навыка не ниже 0,50.

ML-адаптивная стратегия достигала критерия в среднем за 73,3 задания, а случайная — за 84,6. Разница составила 11,3 задания, или 13,4%. Доверительный интервал разницы — от 8,2 до 14,6 задания, p < 0,001. В пределах заданного горизонта порог достигли 70% обучаемых при адаптивной стратегии и 25% при случайной.

Также модель сравнивалась с классическими подходами Elo, online IRT-2PL, BKT и PFA на одном и том же разделении пользователей. Значения Brier score составили: ML — 0,1891; IRT-2PL — 0,2016; Elo — 0,2019; PFA — 0,2184; BKT — 0,2483. Для Brier score меньшее значение соответствует более точному вероятностному прогнозу.

Все перечисленные результаты получены на синтетических данных. Они показывают работу алгоритма в контролируемой симуляции, но не доказывают педагогическую эффективность на реальных студентах. План последующей проверки описан в docs/HUMAN\_VALIDATION\_PROTOCOL.md.

## Технологии

Backend написан на Python с использованием FastAPI, Pydantic и SQLAlchemy. Данные хранятся в SQLite. Для обработки данных и машинного обучения используются pandas, NumPy, scikit-learn и joblib.

Frontend разработан на React 18. Для сборки применяется Vite, для запросов к API — Axios.

## Запуск backend

Рекомендуется Python 3.11 или 3.12.


cd backend
python -m venv .venv


Активация окружения в Windows PowerShell:

powershell
.venv\\Scripts\\Activate.ps1



В Linux или macOS:


source .venv/bin/activate


Установка зависимостей и запуск сервера:


pip install -r requirements.txt
uvicorn app.main:app --reload


После запуска backend доступен по адресу http://127.0.0.1:8000, а документация Swagger — по адресу http://127.0.0.1:8000/docs 

Для размещения приложения на сервере необходимо задать собственное значение переменной ADAPTIVE\_JWT\_SECRET.

## Запуск frontend




cd frontend
npm install
npm run dev


Приложение будет доступно по адресу http://127.0.0.1:5173.

## Проверка проекта

Основные backend-тесты запускаются командой:


cd backend
python -m pytest -q -m "not slow"


Отдельный полный тест обучения модели:


python -m pytest -q -m slow


Для воспроизведения проверки данных, оценки активной модели и исследовательской симуляции используются команды:


python scripts/run\_quality\_checks.py
python scripts/evaluate\_active\_model.py
python scripts/run\_research\_suite.py --simulation-learners 60 --simulation-steps 90 --robustness-learners 24


Сборка frontend:


cd ../frontend
npm run build


Подробное описание методики и результатов находится в docs/RESEARCH\_METHODS\_AND\_RESULTS.md, архитектура ML-части — в docs/ML\_ARCHITECTURE.md.
